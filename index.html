05 / Approach

Curiosity is a start.
Evidence is the work.

The aim isn't to make projects look more advanced than they are. It's to understand a problem, build something real, test its limits, and explain what I learn.

01 / Understand

Start with the system

Define the problem and its constraints before choosing tools or writing code.

02 / Build

Make it observable

Prefer clear behaviour, useful status information, and failure paths that can be understood.

03 / Refine

Document the limits

Separate what has been implemented, what has been tested, and what still needs evidence.
